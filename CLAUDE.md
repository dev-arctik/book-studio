# CLAUDE.md

Scanned ISKCON books → clean, diacritic-correct PDFs for kids at a charity youth forum. Two parts: `manual/` (the hand-run pipeline every finished book was made with — run steps in `manual/README.md`) and `software/` (Book Studio, a desktop app wrapping that pipeline — **shelved since 2026-10-19**, see below; details in `software/README.md`). The root `README.md` is for users of the software (why it exists, install, use) — keep book lists out of it; `manual/README.md` has the run steps and the local folder map; `workspace/STATUS.md` in the library (local, never in git) has which books are done. This file holds the rules, preferences and pitfalls.

## Where things stand (2026-10-19) — read this first

**Books are made with the manual pipeline, supervised by Claude Code.** Book Studio (the app) is shelved — kept in the repo, unused, maybe revived later. Why: the app runs the same pipeline but without judgment. Text, diacritics, design, PDF and EPUB come out right automatically; **working out a book's chapters** does not — every book with an unfamiliar layout needs someone to read its `report.txt`, compare with the scan and add the right settings or rule. That judgment is what made the 13 finished books good, and it is what Claude does in a session. Ideas for putting it into the app (a local AI, calling `claude -p`, a self-improving loop) were weighed and parked.

**Work moves to the Windows laptop** (ASUS TUF F15: i5-10300H, 24 GB RAM, GTX 1650 4 GB, Windows 11 with Smart App Control). Devansh works there in Claude Code (Desktop app or CLI). The Mac's copy of Book Studio was uninstalled. The book-specific hand-over (which books are on the laptop, how far each got, what's odd about them) is in `workspace/STATUS.md` in the library — local, never in git, carried to the laptop by hand. Every book needs an entry in `book_meta.json` (at least `title` and `layout`) before `assemble`/`typeset` run.

## Hard rules

- **Book content is never published.** The PDFs are internal ISKCON material, not released online: no public uploads, no artifacts/publishing, no book content on GitHub. Sending book content to **Claude** (Claude Code, or Book Studio's optional Claude step for working out chapters) is allowed — Devansh decided on 2026-10-19 that the books going to the cloud for this is fine; other cloud services are not. The repo goes to a **public GitHub repo** (approved 2026-10-18, so Book Studio can self-update from GitHub Releases) — code and docs only: `.gitignore` keeps out `books/`, `output/`, every .pdf/.epub/.docx and `book_meta.json`, which lives in the library, not the repo (it holds titles, captions and OCR-fix text fragments); release zips leave it out too. Never force-add book files; creating the repo, pushing and publishing releases are confirmed with Devansh first. The OCR (Surya via a local `llama-server` on 127.0.0.1) and typesetting (Typst) are fully local — keep it that way.
- **Nothing installed globally on the Mac** (low on disk; the Windows laptop may use global Python and Poetry). Poetry venv and cache, HF model cache (`HF_HOME`), Surya `MODEL_CACHE_DIR`, the `llama-server` binary and fonts all live inside the project. `manual/pipeline/local_env.py` pins these (`PIPELINE_DIR` = the scripts, `PROJECT_ROOT` = the repo root where books, output, tools and caches live) — every pipeline script imports it first.
- **The laptop must rest while it reads pages — never skip it.** Reading pages keeps the CPU and GPU at full load for hours, and a hot laptop slows down (the pages went from about 22 to 38 s each when it heated) and wears out faster. Devansh's rule (2026-10-20, the same idea as Book Studio's work/rest settings): **15 min of rest after every 60 min of reading, and 30 min of rest after every finished book** before the next one is read. It is built into `ocr_book.py` / `power.py` (`WORK_MINUTES`, `REST_MINUTES`, `BETWEEN_MINUTES`; the `.last-ocr-finished` marker in the workspace holds when the last book ended). Never start OCR in a way that bypasses it (not `BOOK_NO_COOLDOWN=1`, not another OCR script), never shorten it, and when a book was read by an older process without it, create the marker yourself so the next book still waits. Do the checking and fixing of the finished book during the rest, so the wait costs no time. Changing the rest times is Devansh's call. Digital (no-OCR) books need no rest. **Never OCR a book that has a real text layer** (Devansh, 2026-10-20: "most of the PDFs are actual originals, why waste time and resource"): before queuing OCR, measure the PDF's text (characters per page, a page-sized image under it, stand-in or private-use letters); a good layer goes through `pdf_to_book.py`, with `sections` in `book_meta.json` when the PDF has no outline (see `manual/README.md`). Only real scans, or text layers that are broken (split diacritics like Sri Hari-nama's, private-use codes), are read by OCR.
- **Check every book after its run — before publishing (Devansh, 2026-10-23: "checking after the pipeline is run is very crucial").** Run `qa_book.py <batch folder>` and then look at the result yourself, page by page where it matters, against the original. Always check: (1) **the cover** — page 1 of the PDF and the EPUB cover are the cover image Devansh supplied for that book (a white title page is not a cover; look in the batch folder for the image — The Heart of Transcendental Book Distribution once went out without it); (2) **the contents** lists every chapter *and* the topics inside each chapter, as the original's contents does (PDF bookmarks and the EPUB contents too); (3) **headings** such as "SECTION 13" and "TRANSLATION" are centred, as are centred headings and numbers of the original ("(1)", "The Ten Offences"); (4) **Sanskrit words are bold** in word-for-word glosses; (5) **verses** are aligned as in the original (centred lines, the original's line breaks); (6) **paragraphs** stay whole — no stray fragments or text outside the paragraph (a justified line some PDFs store word by word was once cut into pieces); (7) **pictures** from scans are sharp (render at 300 dpi, sharpened; fail below 150 dpi); (8) only Gentium in the PDF; (9) no lost-ligature words (Te, afer); (10) **the dedication page** — whole paragraphs, no broken lines, no ornament text (Devansh, 2026-10-26; `tidy_dedication` handles the usual cases). Fix what fails by improving the pipeline or the book's settings, rebuild and check again — never publish a book that has a FAIL.
- **Faithful to the original.** Fix OCR errors (checked against the scan); never "correct" the printed book's own typos or spellings.
- **Never touch the user's personal files** (e.g. in ~/Downloads); only files explicitly named as books.

## User preferences

- **One PDF per book.** No chapter-wise PDFs, no duplicate copies of book content. The user cuts chapters by hand.
- **Clean folder.** Temporary files (crops, Typst data, previews) are deleted after use; no `__pycache__` (scripts set `sys.dont_write_bytecode`); scratch renders go in `.cache/tmp/` and are removed.
- **Finished book** → `pdf/<book>_en.pdf` (or `_hi`) and `epub/<book>_en.epub` in the book's batch folder (`group1/pdf`, `group1/epub`), one folder per format (Word copies, if ever made, in `word/`; per-format folders asked for 2026-10-18, flat in the library 2026-10-20; `local_env.final_path()` picks the folder). Only a **checked** book goes there — `publish_book.py` copies it from the workspace; drafts stay in `workspace/<book>/`. The original is never moved or copied into the library. Book Studio does the same with `PDF/` and `EPUB/` in its output folder. Never name a file `_clean`.
- **Design is approved — don't change it unasked:** A5, Gentium Book Plus, brown accent `#7a4a12`, centred verse blocks, bold Sanskrit words in word-for-word, no copyright line on the title page. The book's own copyright page (©, ISBN, publisher — found among the front pages by two or more such signs, OCR text or the PDF's own text) is kept when `keep_copyright` is set — Book Studio's "Keep the book's copyright page" checkbox, **on by default** (user asked 2026-10-18); in the manual pipeline it is opt-in per book in book_meta.json, so the 13 finished books have none. It is never typed in by us. Every PDF opens with the original front cover (page 1 of the scan, colour, its own page shape) — the user asked for it on 2026-10-16; the EPUB uses the same cover.
- **Commits:** local commits need no confirmation (Devansh, 2026-10-20) — commit tested pipeline and docs changes with a detailed message. **Pushing, releases and anything public are still confirmed with him first.**
- Ask before starting a multi-hour OCR run; the user may want to control when the Mac is busy.

## Pipeline

**Code and books live apart.** The repo (`book-studio/`, public) holds only code and docs; books and `book_meta.json` live in the **library** folder outside it (here `../book-library`: `workspace/`, `pdf/`, `epub/`). Software — llama-server, fonts (`tools/`) and the OCR model (`.cache/models-gguf`) — stays with the code in the repo, git-ignored (user's choice 2026-10-18; Book Studio keeps its own copies in its data folder). Every script takes the paths explicitly — the book's file and `--library` (or `BOOK_LIBRARY`); nothing is looked up in a default place (user asked 2026-10-18): `poetry run python manual/pipeline/run_book.py <path/to/book.pdf> --library <path/to/book-library>`, run from the repo root. The book's key is the file name without `.pdf`. `run_book.py` = `ocr_book.py` → `assemble_verses.py` | `assemble_prose.py` (chosen by `layout` in `book_meta.json`) → `typeset_book.py` → `book_to_epub.py`, all into the workspace; `publish_book.py` then moves a checked book out.

| File | Role |
|---|---|
| `local_env.py` | Reads `--library` (or `BOOK_LIBRARY`; Book Studio sets `BOOK_STUDIO_DATA`) and stops with a usage message without it; paths, the workspace and its numbered stage folders (`1-ocr`, `2-assembled`, `3-clean-pdf`, `4-epub`, `logs`); `book_path()` (the command-line PDF, must exist) and `find_book()` (by key: the path given this run, else `books/` in Book Studio's data folder); `final_path()` (`pdf/`, `epub/`, `word/` in the library); local cache env vars |
| `ocr_book.py` | Surya OCR, 4 pages per call, resumable (skips existing `page-NNN.json`); `--fix page:block` re-OCRs one block from a tight crop |
| `ocr_text.py` | Shared helpers: HTML clean-up, non-IAST look-alike fixes (`î→ī`, `ş→ṣ`, `○→O`…), line joining, paragraph gluing across page breaks, title matching, back-cover removal, `text_fixes` |
| `assemble_verses.py` | Verse anthologies (Padyāvalī): chapters from "title + (English title)" headings, verses by "Verse N", word-for-word/translation/poet state machine, title reconciliation against the contents page |
| `assemble_prose.py` | Prose books (Vraja-līlā): sections matched **in order** against the book's own contents list; blocks = p / epigraph / quote / cite / sign / h / figure |
| `figures.py` | Crops illustrations: mid-tone region + dark border lines on all 4 sides = framed photo (crop inside frame); else trim margins. Skips ornaments (<5% of page, or top 6% of page). Keeps colour when ≥5% of the crop is clearly saturated (paintings, photo plates); grey scans stay greyscale |
| `typeset_book.py` | Converts either layout into one template format; crops figures into `3-clean-pdf/.build/` and deletes it after compiling. Photos on the skipped front pages (page 2 → contents page: dedication portrait, Deity photo) become frontispiece pages after the title page — it prints each one; check against the scan and list line-art ornaments in `frontispiece_skip` |
| `book_template.typ` | The page design (Typst). Reads JSON via `sys.inputs.data` — never escape book text into Typst code |
| `book_meta.json` | Per book: title, subtitle, author, credits, `layout`, `academic` (page footnotes + indented quotations, geometry-based), `unnumbered_sections`, `text_fixes`, `figure_captions` |
| `pdf_to_book.py` | Stage 2 for clean digital PDFs (no OCR): outline → sections, paragraphs by first-line indent (opt-in `margin`/`indent` rules in pdf_text), drop caps rejoined, check-mark-icon list items, tables rebuilt from small print using drawn cell edges (zebra rows defeat `find_tables`), centred lists, verses/translations/[sources] → same `book.json` |
| `book_tidy.py` | Digital route clean-ups, on with `"tidy": true`: verse + translation blocks, bold subheadings, signatures, centred breaks, capital openings |
| `pdf_text.py` | Shared reader for text PDFs (used by the two below): lines → paragraphs by line gap, headings by size, bold/italic, verse breaks; decodes old **Balaram**-font diacritics ("Kåñëa" → Kṛṣṇa) |
| `pdf_to_epub.py` | Text PDF with an outline → `.epub` beside it: chapters from the outline, cover from page 1, copyright and printed-contents pages left out |
| `book_to_epub.py` | Processed book (`book.json`) → `workspace/<book>/4-epub/<book>.epub` with all figures; reuses `typeset_book.build_typst_data` (same crops as the PDF). Verse anthologies too (verse no., centred Sanskrit, bold-word gloss, translation, poet) |
| `publish_book.py` | The last step, only after a book is checked: copies its PDF and EPUB drafts from the workspace to `pdf/<book>_en.pdf` and `epub/<book>_en.epub` in the library; refuses if a draft is missing |
| `epub_pack.py` | Shared EPUB packaging: XHTML template, CSS matching the PDF design, clickable nav + toc.ncx, cover, Gentium embedded |
| `pdf_to_docx.py` | Text PDF → editable `.docx` beside it (PyMuPDF lines → paragraphs by line gap, headings by size). Not `pdf2docx`: it works per character and corrupts Devanagari at line joins ("बड़ाायोगदान") |

Run Python with `poetry run python` (Python 3.12 from Homebrew; system 3.9 is too old for Surya).

The window shows a power line while working and a reminder when a run starts on battery.
- On opening, the app checks for updates first ("There is an update — do you want to update now?"), then setup. Book settings are re-read by the worker just before the PDF and the build is fingerprinted at the typeset stage, so edits made while pages are read go into that build.

## How to verify (do this every time)

- **Unusual books** (prose route): when under half of the contents entries match (`CONTENTS_TRUST`), `assemble_prose.find_chapters()` tries, in turn, the contents with unlimited look-ahead, the headings on the pages (`headings_contents`: repeated running heads, labels and everything up to the contents page left out) and one whole-book section — so the book is still made; `book.json` gets `structure` (method, listed, found) and Book Studio marks it "Ready — chapters need a look". Books that match (all 13 finished ones) take the unchanged first path. `report.txt` ends with a **book map** (where the contents was read, every entry ✓/✗, the headings on the pages, each miss with its nearest heading) — volunteers send it with Check book → **Copy report**; the run card's Copy report sums up every book of the run (`software/book_studio/report.py`). Tune from it with `book_meta.json` settings (Book fixes).
- Known quirk: a contents title starting with the word "I" ("I Went Home…") matches `TOC_ROMAN_RE` and turns on the Roman-numbered rules (only numbered rows kept) — seen in a test, not yet in a real book.
- **`report.txt` is the source of truth for completeness.** Verse books: verse numbers continuous, every contents entry found. Prose books: every contents entry found in order, first words of each chapter sane, no unexplained blank pages. Check every flag against the scan (render with `pdftoppm` into `.cache/tmp/`, view, delete).
- **After changing shared code, prove finished books didn't change.** The 13 finished books' OCR work (`output/`, now called `workspace/`) was deleted on 2026-10-18 at the user's request, so they can no longer be rebuilt without re-reading every page; compare instead against a book whose `workspace/<book>/` still exists, or OCR a short book (A Spiritual Journey, 78 pages ≈ 30 min) and compare its PDF text with the finished PDF in `pdf/`. Say plainly when a change could not be checked this way.
- Render a few pages of the new PDF and look at them before calling a book done; `pdffonts` should list only Gentium (a fallback font means a character Gentium lacks).
- **Bold and italic must survive** (the user checks this): italic Sanskrit terms and book titles, bold names, bold Sanskrit words in word-for-word glosses. Compare `<i>`/`<b>` span counts in `1-ocr/` with those in `2-assembled/book.json` per chapter (a chapter that loses them all means emphasis was stripped), and compare rendered pages with the scan side by side.

## OCR pitfalls already seen (and handled)

- Script-font headings misread: "Terse 45", "Verse .90", "Verse 28.3" → tolerant `VERSE_RE`.
- A heading labelled `PageHeader` ("Verse 80" at page top) → kept if it matches a verse heading.
- Chapter title + English title arriving as one block, two-line titles, or brackets dropped → three title shapes in `assemble_verses.py`; poet lines and "(Note: …)" footnotes must never count as titles.
- First Sanskrit line replaced by the first word-for-word line → re-OCR the block with `--fix`.
- `p` read as `ṭ` in titles ("Goṭī") → reconciled with the contents-page reading by word frequency, letter-level only.
- Contents page returned as one big picture (`<img/>`) → report's blank-page and contents checks catch it.
- Decorated drop caps: first letter misread ("Ifter") or second line damaged ("lego", "lobeisances") → `text_fixes`.
- Captions inside a picture's box are never OCR'd → `figure_captions`.
- Contents as "Chapter 1" (no page) + first place row + more place rows (A Spiritual Journey): the place rows are subheadings; closing sections after the last chapter must be listed in `unnumbered_sections`.
- Facsimiles (a newspaper clipping, a letter of Prabhupāda) get OCR'd as text — list their pages in `facsimile_pages` so the page becomes one picture + its caption.
- Italic letters with line breaks look like verses — books without verses set `italic_prose` (multi-line italic English is not separable from Tava's italic verse translations by any measure).
- Section headings that differ from the contents title ("Srila Prabhupada" printed as "His Divine Grace A.C. Bhaktivedanta Swami Prabhupada") → `heading_aliases` in `book_meta.json`. Indented letters without footnote handling → `inset_quotes` (`academic` = inset quotes + page footnotes).
- A font whose ṛ dot sits too low: the OCR reads "Krṣṇa" for the printed Kṛṣṇa (Dāmodara-jananī, 1,640 words) → `restore_r_dot` (vocabulary = the book's own correctly read ṛ words). Contents with dotted leaders, chapter labels as headings and paragraph entries → `contents_rows`. An index not in the contents plus endpapers → `last_page`.
- Scans with pages out of order (swapped pairs, duplicates, pages re-scanned and added at the end — When the Sun Shines): check printed page numbers, then `skip_pages` + `page_moves` [[page, after]]. Sections the contents doesn't list (a photo gallery, a Part whose title page has no heading) → `insert_sections` (kind, subtitle, `gallery` attaches text captions). OCR'd tables → `ocr_tables` (opt-in: Saṁskāras and Dancing White Elephants have Table blocks that were checked as text).
- A contents page set as plain text lines ("Foreword by Radhanath Swami ix") → `contents_pages` (read for the contents only, never for headings — its lines would match their own titles) + `chapter_subentries` (lines under a chapter are its subheadings).
- Labels glued to titles by the OCR ("CHAPTER EIGHTQUESTIONING…", "PART ONEASPECTS…") → `NUMBERED_LABEL_RE` strips number-word labels before matching; "Appendix 1: …" contents rows match their page heading without the prefix. Italic multi-line "headings" are verses. Part pages with a painting under the title (not a full-page cover) show it via the template's part-page.
- Running heads the OCR tags as headings ("Chapter Three : Bhaktivedānta!" on every page — Without Fear) → `running_heads` patterns, dropped only in a page's top 8% (the same words lower down are real labels). Contents with the page number first ("17 WITHOUT FEAR") and all-caps titles → handled in `contents_pages` mode + `smart_title`. Ņ/ņ (cedilla N) is never IAST → mapped to Ṇ/ṇ in `ocr_text.py` (ü is not: real in Müller, Krüger).
- Back cover (blurb, ISBN, barcode) leaking into the last chapter → `drop_back_cover`; a back cover without an ISBN (Saṁskāras) = the unnumbered last scan page with a picture covering ≥30% of it (a text-only closing page like Vraja's stays).
- Front-page photos need their own test: a faint swirl and Prabhupāda's pencil portrait look alike to any pixel measure, hence `frontispiece_skip` per book.
- Running headers returned as headings ("Yavat Part One" on every page) → dropped when they repeat the current section title.
- The contents page's own lines matching the titles they list → excluded from heading detection.

- Prose-book structure varies: contents as "Title – page" lines (Vraja), table rows (Tava, Saṁskāras), Parts with full-page paintings (Tava), Roman chapters whose numbered sub-sections are subheadings (Saṁskāras), front sections printed before the contents page, contents titles longer than the page heading → handled in `assemble_prose.py` (row-based contents, look-ahead matching, prefix/colon/bracket title matching).
- Endnotes under "NOTES" and page-bottom `Footnote` blocks → small-print Notes at the section end; `<sup>` markers kept.
- Scanner debris: text strips in the outer 8% side margin, blank versos detected as full-page "pictures" (kept only as Part paintings).
- A lowercase paragraph continues an earlier one — glued across pictures/verses, but never onto a paragraph that ended with . ! ?
- Characters Gentium lacks (♦ ► ▪ ➤ □ ⇒ ′ …) are mapped in `ocr_text.py`; `pdffonts` must show only Gentium.
- A "digital" PDF in an old diacritic font (Balaram) without a letter mapping extracts as private-use codes (U+F0xx) — boxes in our PDF. It is not digital for us: read its pages with OCR (Book Studio's `worker.is_digital()` checks for this; with the manual pipeline, choose the scan route). Unicode Balaram text ("Kåñëa") is different and is decoded by `pdf_text.py`.
- Books over 999 pages (Toward His Smiling Face, 1086): the page files were sorted by name, so `page-1000` came before `page-101` and every section after page 100 was jumbled → `ocr_text.ocr_pages` sorts by page number. The overview series (The Backward Glance, The Veil, Toward, Unveiling) opens chapters mid-page: `insert_sections` takes `"at": "<regex>"` to open a section at the matching heading; italic "Texts 1–7: …" lines are headings; `no_topics` keeps hundreds of such lines out of the contents; a page the reader takes for one big picture (a divider with only "CANTO NINE") is dropped with `drop_pictures`; genealogical charts are `facsimile_pages`; plain-titled back matter is `kind: back` so it gets no chapter number.
- Contents shaped as chapter rows with lettered stories (a), (b)… under them, and one big line repeated above every story's title: chapters = the chapter rows, stories = subheadings, the big line = `running_heads`. The book map at the end of `report.txt` shows such patterns.

## Typst gotchas

- Don't name a variable `v` — it shadows the `v()` spacing function.
- `block()` without `width: 100%` shrinks to its content, so "centred" text hugs the left margin.
- Gentium lacks `✦` (falls back to a math font) — the ornament is drawn with shapes.
- Typst only reads files under the project root, hence the temporary `.build/` folder.
- Paths passed to Typst must use `/` — on Windows `str(path)` has backslashes and Typst refuses them ("path must not contain a backslash"); build them with `typeset_book.typst_path()`.
